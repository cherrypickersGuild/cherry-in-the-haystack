2. 빠진 것

idea_group 폐기

같은 의미 그룹인데 매핑 테이블의 extracted_concept 텍스트가 행마다 달라 정규화 의미 무력화. → concept 로 단일화.

evidence_metadata 폐기

점수가 paragraph 와 1:1 관계인데 별도 테이블이라 JOIN 만 늘어남. → paragraph_chunk 컬럼으로 흡수.

key_idea 폐기

코드에서 사용 흔적 없음.

3. 추가된 것

concept 신규

표제어 1개 = DB 1행. 정규화 본질 회복. idea_group 의 대체.

concept_alias 신규

"RAG" / "rag" / "검색 증강 생성" / 오타 등 변형을 같은 concept_id 로 매핑. 검색어 흔들려도 같은 결과.

topic 신규

큰 분류 마스터 (예: "Retrieval Systems"). 자유 텍스트 컬럼 handbook_topic 을 대체.

subtopic 신규

topic 하위 분류 (예: "RAG", "Hybrid Search"). 두 단계 hierarchy 제공.

evidence_verification 신규

사람이 evidence 품질을 검증한 기록 (verdict: verified / flagged / rejected / needs_review). writer 가 검증된 것만 쓰도록 필터링 가능.

4. 재설계된 것

knowledge_verification_contributor 재설계

BIGSERIAL → UUID, app_user 와 FK 연결 가능, evidence_verification 과 매핑되어 고립 해소.

5. 유지되는 것 (구조 동일, FK 정책만 강화)

book · chapter · section · paragraph_chunk · paragraph_concept_link · paragraph_embedding · processing_progress

모든 FK ON DELETE RESTRICT + soft delete (revoked_at) 적용. CASCADE 폭발 삭제 방지.

6. v2 의 5가지 핵심 변화

테이블이 왜 빠지고 추가됐는지의 배경 — 5가지 설계 원칙으로 정리.

1

표제어를 별도 테이블로 명시화

"같은 개념 = DB 한 행" 보장

Before paragraph_concept_link.extracted_concept (텍스트)
→ 매핑 행마다 다른 표면 표현
→
After concept.canonical_name (UNIQUE)
매핑은 concept_id (UUID) FK 만

효과 · "Retrieval-Augmented Generation" 이라는 개념이 DB 에 단 1행. 검색 키 단일화.

2

Alias 로 변형을 사전 등록

표제어의 다양한 표현을 한 concept 으로 모음

Before 변형 처리 없음
"RAG" 와 "Retrieval-Augmented Generation" 이 별개 텍스트로 저장
→
After concept_alias 테이블
"RAG", "rag", "검색 증강 생성", 오타 등
모두 같은 concept_id 가리킴

효과 · 사용자가 어떤 표현으로 검색해도 같은 concept 결과. 운영자가 alias 등록만 하면 됨.

3

링크 테이블에서 표제어 제거 (정규화 회복)

매핑 테이블은 순수 매핑만 — 텍스트 0

Before paragraph_concept_link:
• idea_group_id
• extracted_concept (텍스트)
→
After paragraph_concept_link:
• paragraph_chunk_id
• concept_id (FK)
• is_primary, extraction_confidence

효과 · 같은 (paragraph, concept) 쌍에 한 행만. UNIQUE 제약으로 중복 차단. 검색은 무조건 concept_id 기준.

4

Topic / Subtopic 마스터 테이블

분류를 자유 텍스트 → 정해진 집합

Before handbook_topic VARCHAR(100)
→ 같은 의미 다른 표기 ("RAG" vs "rag" vs "검색")
→
After topic + subtopic 마스터 테이블
concept.topic_id / subtopic_id FK
(둘 다 NULL 허용)

효과 · 분류 값이 정해진 집합 안에서만 쓰임. topic 만 / topic+subtopic / 둘 다 NULL 모두 가능.

5

CASCADE 제거 + Soft Delete

실수 한 번에 데이터 폭발 삭제 사고 차단

Before ON DELETE CASCADE / SET NULL
→ book 1행 삭제 시 chapter, section,
paragraph_chunk 수천 행 폭발 삭제
→
After ON DELETE RESTRICT (전부)
revoked_at TIMESTAMPTZ NULL
(실제 삭제 대신 표시)

효과 · 자식 있으면 부모 삭제 막힘. 잘못 지웠어도 UPDATE ... SET revoked_at = NULL 로 복구 가능.

💡 에이전트 작업자에게: DB 구조는 크게 바뀌었지만 받는 JSON 형태는 그대로. 핵심 변경은 chunk_id 등 ID 가 정수 → UUID 문자열, comment_type → extract_type (ENUM 9종), 그리고 신규 옵션 필드 (concept_id, handbook_topic, handbook_subtopic) 정도.
