Agent API 스펙

기준일 2026-05-02 · writer_agent / news_agent 통합 가이드 · handbook v2 반영

1. 한눈에 — 사용 가능한 endpoint

베이스 URL: https://api.cherryinthehaystack.com/api/v1/agent
인증: x-agent-api-key 헤더 필수

POST /agent/insert-article

기사 한 건 삽입 (URL 중복 자동 스킵, source 자동 생성). news_agent / scraper 가 사용.

GET /agent/ask-evaluation?type=&version_tags=

평가 패키지 한 번에 받기 — prompts + catalog + items. news_agent 가 평가 작업 시작 시 호출.

GET /agent/get-prompts?type=&version_tags= NEW

프롬프트만 따로 받기 — A/B/C 같은 여러 버전을 한 번에. writer_agent 등 평가 외 용도.

POST /agent/finish-evaluation

평가 결과 저장 — agent 가 LLM 호출 끝낸 결과 JSON 을 백엔드로 반환.

주요 필드 — 한눈에

필드타입변경 여부비고
chunk_iduuid string타입만 변경전: int → 후: UUID 문자열
book_id / chapter_id / section_iduuid string타입만 변경모두 UUID
concept_namestring출처 변경이제 정식 명칭(canonical_name) 만 옴
extract_typeenum이름+값 변경전: comment_type 자유텍스트
후: extract_type ENUM 9종 (DEFINITION/EXAMPLE/CASE_STUDY/METRIC/PROCEDURE/PRINCIPLE/COMPARISON/WARNING/OTHER)
concept_iduuid string신규그래프 호출 시 사용
extraction_confidencefloat (0~1)신규매핑 신뢰도. 낮은 거 필터링 가능
handbook_topic / subtopicstring?신규분류 마스터에서 옴 (NULL 가능)
judge_originality / depth / technical_accuracyfloat (0~1)출처 변경전: evidence_metadata 별도 테이블
후: paragraph_chunk 컬럼 직접

4. Topic 매칭 흐름

1
사용자 topic 입력 → 백엔드 수신
예: "RAG", "검색 증강 생성", "Retrieval-Augmented Generation"
2
canonical_name 정확 매칭 시도 (case-insensitive)
handbook.concept.canonical_name 과 비교
3
실패 시 → alias 매칭 시도
handbook.concept_alias.alias_text 와 비교 → 매칭된 concept_id 획득
4
concept_id 로 paragraph_concept_link → paragraph_chunk JOIN
결과를 evidence_rows[] 에 패딩 → 에이전트로 전달
왜 alias 가 중요한가: 사용자가 "RAG" 입력해도, "rag" 입력해도, "검색 증강 생성" 입력해도 → 모두 같은 concept 의 evidence 받음. 운영자가 alias 만 잘 등록해두면 됨.

5. 에이전트 작업자 적응 가이드

코드 변경 불필요

body_text, page_number, paragraph_index, book_title, book_author, is_primary, judge_* — 그대로 사용

최소 적응 필요

변경대응
ID 가 정수 → UUID 문자열산술 연산 없음. string 비교/전달만 함
comment_type → extract_type코드에서 필드 이름 교체. 값 비교 시 ENUM 9종 (대문자) 가정

옵션 활용 (무시해도 OK)

필드활용
handbook_topic / subtopic글에 카테고리 표시
extraction_confidence낮은 매핑 제외 필터링
concept_id그래프 호출에 사용
호환성 보장: writer_agent 가 반환하는 output JSON 형식 (summary, why_it_matters, evidence[], related_concepts[], references[], updates[], patch_notes[]) 은 변경 없음. 기존 클라이언트와 호환.
합의 필요 사항: ① GraphDB 직접 조회 유지 여부, ② evidence_verification.verdict = 'verified' 필터 적용 여부, ③ Update Payload 출처 테이블 결정.
