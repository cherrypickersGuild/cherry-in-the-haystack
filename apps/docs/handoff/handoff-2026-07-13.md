## 1. ⭐ 개발 정책 (이 사용자와 일하는 방식 — 반드시 지킬 것)

> 사용자가 명시적으로 남겨달라고 한 항목. 위반 시 강하게 지적받음.

1. **탐색은 자유, 변경은 허락 후.** 파일 읽기·grep·코드 탐색은 자유. 하지만 **Edit/Write/Bash/git/설치/서버실행 등 "변경·실행"은 반드시 먼저 설명하고 동의를 받은 뒤** 진행. ("니가 맘대로 하지마" — 세션 중 여러 번 강조됨)
2. **"도와줘" ≠ "대신 해줘".** 기본은 **명령어를 알려주고 사용자가 직접 실행**. 서버 실행·DB 마이그레이션 적용·배포는 **사용자가 직접** 함 (IntelliJ/터미널/Dokploy). 무거운 작업(install/build/server)은 실행 전 반드시 물어볼 것.
3. **큰 기능은 "구현 기획서(md)" 먼저.** 바로 코딩하지 말 것. **충분히 논의 → 기획서 작성 → 여러 번 검토(사용자가 "한번 더 검토" 반복 요청) → 그 다음 구현.** 검토에서 실제 코드와 대조해 진짜 문제를 잡는 걸 중요하게 여김.
4. **좁은 해석.** 지시한 것만 정확히. 이름 변경·기본값·부수 정리 등 파생 결정은 별도 허락 대상. 옵션으로 제시하고 선택을 기다릴 것.
5. **커밋/푸시/배포는 지시할 때만.** 사용자가 직접 커밋하는 편. 삭제·덮어쓰기 전엔 대상 내용을 먼저 확인하고 판단 근거를 제시.
6. **응답 언어: 한국어.**
7. **정확성 우선.** 코드/DB를 실제로 확인하고 말할 것(추측 금지). 되면 됐다고, 안 되면 로그와 함께 솔직히.

## 2. 환경 / 스택

- **모노레포 (pnpm)**: `apps/api`(NestJS), `apps/web`(Next.js), `apps/contracts`, `python_services/*`
- **DB**: Supabase PostgreSQL. `apps/api/.env`의 `DATABASE_URL`. **로컬·프로덕션이 같은 DB 공유** (중요!)
- **Redis**: 로컬은 **포트 16379** (`apps/api/src/config.ts`에 하드코딩). 실행: `redis-server --port 16379 --daemonize yes` (brew redis 설치돼 있음). 부팅 자동실행은 `/opt/homebrew/etc/redis.conf`에서 `port 16379`로 바꾼 뒤 `brew services start redis`.
- **배포**: **Dokploy** (수동 배포). GitHub Actions 자동배포 워크플로는 실패만 떠서 삭제함. 배포는 Dokploy UI에서 web/api 각각 Redeploy.
- **인증**: JWT (`@nestjs/jwt` + `passport-jwt`). accessToken은 프론트 localStorage, refreshToken은 쿠키 + Redis. JWT 전략은 `apps/api/src/common/basic-module/auth.module.ts`(`AuthModule`, `RoleJwtStrategy`).
- **로컬 실행**: `cd apps/api && pnpm start:dev`(:4000), `cd apps/web && pnpm dev`(:3000). node_modules 설치됨. tsc 검증: 각 앱에서 `npx tsc --noEmit`.
  - 참고: `kaas-credit.service.spec.ts`(api), `kaas-admin-page.tsx`/`kaas-dashboard-page.tsx`(web)에 **기존부터 있던 무관 tsc 에러**가 있음 — 우리 작업과 무관, 무시.

## 4. 완료 작업 ②: 벤치마크 — 회원별 Claude API 키

> **배경**: Workshop의 "카드 조립 → 벤치마킹" 실행 LLM을 공용 `.env` 키가 아니라 **로그인한 회원 본인 Anthropic 키**로. 회원이 Settings에서 등록. (더 큰 그림: "조립식 에이전트"를 회원 자기 LLM으로 돌리기. Claude Code 방식은 후속.)

**기획서**: `docs/bench-member-key-implementation-plan.md` (3회 검토 반영본). 구현이 이걸 따름.

**핵심 설계**
- 키는 **AES-256-GCM 암호화**해서 `core.app_user.bench_api_key_enc`(TEXT)에 저장. 복호화 키 = env `BENCH_KEY_SECRET`. 평문은 DB/로그/응답 어디에도 없음(마스킹만).
- bench `/run`·`/compare`에 **JWT 가드(라우트별!)** 추가 → 회원 키 로드. ⚠️ **컨트롤러 레벨 가드 금지** — 같은 컨트롤러의 `tools/*`(MCP 에이전트용)는 **무인증 유지**해야 함.
- **provider 강제**: 전역 `BENCH_LLM_PROVIDER=flock`이지만, 회원 키가 있으면 **flock 무시하고 Anthropic(claude) + Claude 모델로 강제** + per-call 클라이언트(싱글턴 우회). → 회원 Anthropic 계정으로 과금.
- 실행 에러 세분화: `throw HttpException({statusCode, code, message})`, 프론트는 `err.code`로 분기 (`NO_BENCH_KEY`/`INVALID_API_KEY`/`RATE_LIMITED`/`INSUFFICIENT_CREDITS`).
- **미등록 시**: 벤치 비활성 + "Settings에서 키 등록" 안내 (env 폴백 없음).

**파일**
- DB: `apps/docs/staged_mock/bench-member-key-migration.sql` (`bench_api_key_enc`, **적용 완료**)
- `apps/api/src/utils/crypto.ts` (encryptSecret/decryptSecret/maskKey, AES-256-GCM)
- `app_user`: entity(`bench_api_key_enc`)/`bench-key.dto`/service(`setBenchKey`/`getBenchKeyStatus`/`deleteBenchKey`/`getDecryptedBenchKey`)/facade/controller(`PUT/GET/DELETE /app-user/bench-key`)
- `bench/anthropic.client.ts`: `ClaudeCallInput.apiKey` 추가, apiKey 있으면 Anthropic 강제 + per-call client
- `bench/bench.service.ts`: `run`/`compare`/`runBaseline`/`runEnhanced`에 apiKey 스레딩, `memberFields()`(model=`BENCH_MEMBER_MODEL`)
- `bench/bench.controller.ts`: run·compare에 가드 + `requireBenchKey(req)` + `mapBenchError()`
- `bench/bench.module.ts`: `AuthModule` + `AppUserModule` import (가드·키서비스)

- `RequestWithJwtUser` 타입은 `app-user.controller.ts`에 로컬 정의(export 안 됨) — 다른 데선 인라인 재정의.
