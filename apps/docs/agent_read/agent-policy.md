## 1. ⭐ 읽기는 자유, 변경은 **반드시 허락** (최우선 규칙)

### 1-1. 기본 원칙
- **읽기·탐색은 자유**: Read / Grep / Glob / 조회 전용 명령은 마음대로 해도 된다.
- **변경·실행은 허락 필수**: **파일 수정(Edit/Write), 상태를 바꾸는 Bash, 설치, 서버 실행, 마이그레이션, git 조작** 등 **무엇이든 바꾸는 작업은 먼저 설명하고 사용자 동의를 받은 뒤** 진행한다.
- 허락 없이 임의로 코드를 수정하지 않는다.

### 1-2. 커밋 / 푸시 / 배포는 **명시적 지시가 있을 때만**
- **`git commit` / `git push` / 배포는 사용자가 직접 하거나, 사용자의 명시적 지시가 있을 때만** 수행한다.
- 코드 수정을 마쳤어도 **지시 없이 임의로 커밋·푸시하지 않는다.** 기본은 "**변경만 하고 커밋은 사용자 몫**".
- **배포(Dokploy Redeploy)는 사용자가 직접** 한다. 에이전트가 배포하지 않는다.

### 1-3. **브랜치도 사용자가 정한다** 
- **브랜치를 팔지 말지, 브랜치 이름을 뭘로 할지 — 전부 사용자가 정한다.**
- 에이전트가 `git checkout -b <임의이름>` 을 **먼저 만들지 않는다.** 필요하면 "브랜치를 팔까요? 이름은 뭘로 할까요?" 하고 **물어본다.**

### 1-4. "도와줘" ≠ "대신 해줘"
- 기본은 **명령어를 알려주고 사용자가 직접 실행**한다.
- **서버 실행 · DB 마이그레이션 적용 · 빌드 · 설치 · 배포는 사용자가 직접** 한다 (IntelliJ / 터미널 / Dokploy).
- 무거운 작업(install/build/server)은 실행 전 반드시 물어본다.

### 1-5. 좁은 해석
- **지시한 것만 정확히** 한다. 요청 범위를 넘어 알아서 확장하지 않는다.
- **파생 결정(이름 짓기 · 기본값 · 부수적 정리 · 리팩터링)은 별도 허락 대상**이다. 옵션으로 제시하고 선택을 기다린다.
- 삭제·덮어쓰기 전에는 대상 내용을 먼저 확인하고 판단 근거를 제시한다.

### 1-6. ⭐ 지시를 받으면 **바로 작업하지 말고, 의도·방식을 먼저 설명**한다 (2026-08-01 추가)
- 사용자가 지시하면 **곧바로 코드/파일을 고치지 않는다.** 먼저 ① **그 지시의 의도를 내가 어떻게 이해했는지** ② **어떻게 작업할 것인지(어디를 어떻게)** 를 짧게 설명하고, 확인받은 뒤 실행한다.
- **원본을 재현하라는 지시면 임의로 생략·변형하지 않는다.** 원본 파일·컴포넌트를 **먼저 열어 확인**하고 그대로 따른다.
  - 실제 사례(반면교사): "대표아이콘 제대로 수집" 지시에 로고 대신 랜덤 이모지를 넣거나, "원본 순위표"를 무시하고 임의 리스트표를 만들어 반복 재작업을 유발했다. → 원본(`nd-model-updates-page.tsx`의 `RankCard`·`CATEGORY_LOGOS`)을 먼저 봤어야 했다.
- 애매하면 실행 전에 **물어본다.** "이대로 진행할까요?"로 확인.

## 3. 기획서 프로세스 (큰 작업 필수)

### 3-1. 작성 트리거
- **3단계 이상이 필요한 작업/제안은 반드시 기획서(md)를 먼저 작성한다.** 바로 코딩하지 않는다.
- 흐름: **충분히 논의 → 기획서 작성 → 검토 반복 → 그 다음 구현.**

### 3-2. 검토 규칙 — **최소 3회, 1회마다 멈춤**
- 기획서는 **최소 3회 이상 검토**한다.
- **1회 검토가 끝날 때마다 결과를 보고하고 멈춘다.** (2·3회차를 몰아서 하지 않는다)
- 사용자의 다음 지시가 있어야 다음 회차로 넘어간다.
- 각 회차 보고에 포함: ① 이번 회차에서 본 관점 ② 발견/수정 사항 ③ 남은 리스크·미결정 사항
- 검토는 **실제 코드와 대조해 진짜 문제를 잡는 것**이 핵심이다.

### 3-3. 문서 위치·이름
- 기획서: `apps/docs/<작업명>-implementation-plan.md` 또는 `apps/docs/<작업명>/` 폴더.
- 파악 문서: `apps/docs/agent_read/api-backend-status-YYYY-MM-DD.md`
- 인수인계: `apps/docs/handoff/handoff-YYYY-MM-DD.md`
- 목업: `apps/docs/mockups/`
- **구조를 크게 바꾼 뒤에는 파악 문서를 갱신하거나 날짜를 붙인 새 버전을 만든다.**

### 3-4. 검수표 포맷
범례: `-` 미착수 · `W` 진행 중 · `T` 테스트 통과 · `✅` 검수 완료

## 5. 배포 중심 개발 (Deploy-first) — 로컬 전용 수정 금지

- **커밋되는 소스코드는 항상 "배포 기준"으로 작성·유지한다.** 로컬에서 돌리려고 커밋되는 소스를 로컬 전용으로 고치지 않는다.
- 로컬 실행에 필요한 것은 **커밋되지 않는 수단**으로 해결한다: `.env`(gitignore) / `ENVIRONMENT` 변수.
- ❌ 나쁜 예: `package.json` 스크립트에 머신 절대경로 삽입 → 배포/CI에서 깨짐.
- **`NEXT_PUBLIC_*` 는 빌드타임 값**이다. 바꾸면 **web 재빌드 필요**(api는 재시작이면 반영).

## 6. ⚠️ 이 프로젝트에서 특히 조심할 것

| 심각도 | 항목 | 내용 |
|--------|------|------|

| 🔴 | **회원 API 키·지갑주소·이메일은 외부로 절대 노출 금지** | 로그·응답·분석도구(GA 등) 어디에도 평문으로 보내지 않는다. 마스킹만. |
| 🟠 | **bench 컨트롤러 가드는 라우트별로만** | `run`/`compare`엔 JWT 가드, **`tools/*`는 무인증 유지**(MCP 에이전트용). **컨트롤러 레벨 가드 금지.** |

## 8. 로컬 실행 요약

```bash
# 백엔드 (:4000)
cd apps/api && pnpm start:dev

# 프론트 (:3000)
cd apps/web && pnpm dev

# 타입 검증 (각 앱에서)
npx tsc --noEmit

# Redis (로컬 포트 16379 — config.ts에 하드코딩)
redis-server --port 16379 --daemonize yes
```
