2. 빠진 것 — 왜 뺐나

idea_group 폐기

같은 의미 그룹인데 매핑 테이블의 extracted_concept 텍스트가 행마다 달라 정규화 의미 무력화. → concept 로 단일화.

evidence_metadata 폐기

점수가 paragraph 와 1:1 관계인데 별도 테이블이라 JOIN 만 늘어남. → paragraph_chunk 컬럼으로 흡수.

key_idea 폐기

코드에서 사용 흔적 없음.

3. 추가된 것 — 왜 만들었나

concept 신규

표제어 1개 = DB 1행. 정규화 본질 회복. idea_group 의 대체.

concept_alias 신규

"RAG" / "rag" / "검색 증강 생성" / 오타 등 변형을 같은 concept_id 로 매핑. 검색어 흔들려도 같은 결과.

topic 신규

큰 분류 마스터 (예: "Retrieval Systems"). 자유 텍스트 컬럼 handbook_topic 을 대체.

subtopic 신규

topic 하위 분류 (예: "RAG", "Hybrid Search"). 두 단계 hierarchy 제공.

evidence_verification 신규

사람이 evidence 품질을 검증한 기록 (verdict: verified / flagged / rejected / needs_review). writer 가 검증된 것만 쓰도록 필터링 가능.

4. 재설계된 것

knowledge_verification_contributor 재설계

BIGSERIAL → UUID, app_user 와 FK 연결 가능, evidence_verification 과 매핑되어 고립 해소.

5. 유지되는 것 (구조 동일, FK 정책만 강화)

book · chapter · section · paragraph_chunk · paragraph_concept_link · paragraph_embedding · processing_progress

모든 FK ON DELETE RESTRICT + soft delete (revoked_at) 적용. CASCADE 폭발 삭제 방지.

💡 에이전트 작업자에게: DB 구조는 크게 바뀌었지만 받는 JSON 형태는 그대로. 핵심 변경은 chunk_id 등 ID 가 정수 → UUID 문자열, comment_type → extract_type (ENUM 9종), 그리고 신규 옵션 필드 (concept_id, handbook_topic, handbook_subtopic) 정도.
