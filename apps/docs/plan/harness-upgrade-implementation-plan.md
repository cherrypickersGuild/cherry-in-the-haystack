## 1. 배경 — 평가 요약 (2026-08-07 조사 기반)

조사 출처: code.claude.com/docs (memory·skills·hooks-guide·permission-modes·sub-agents·workflows) + Claude Code CHANGELOG v2.1.200~223.

### 우리 하네스가 더 나은 점 (유지한다 — 건드리지 않음)
1. **방법론의 깊이** — S0~S6·게이트 체계·검토 렌즈·조기 관측은 최신 하네스(플랜 모드 = 단일 게이트)가 제공 못 하는 자산.
2. **강화로그** — 실패→근인→규칙 승격이 git으로 커밋되는 구조화된 팀 학습. auto-memory(개인 머신·비정형)보다 감사 가능.
3. **base-data 상태 인수인계** — 최신 하네스에 아예 없는 영역. 날짜 없는 §9 포인터 패턴 유효.
4. **도구 독립성** — 마크다운이라 aiqops와 공유되고 타 에이전트(AGENTS.md 표준)에서도 읽힘.

### 부족한 점 (이번에 고친다)
| # | 부족 | 실측 근거 |
|---|---|---|

| G3 | **로딩 이분법** | 28KB 지침 통짜. §7의 영역 규칙(bench 가드·상태 네비)은 해당 파일 작업 시만 필요한데 항상 실림. 공식: 자동로딩부 200줄 초과 시 준수율 저하 경고 |

## 3. Phase별 실행 계획

### Phase 1 — 진입점 소생 (G1 해소) 【필수 · ~1분】
- 루트 **`CLAUDE.md` 신설**:
  ```markdown
  @AGENTS.md

  > 위 인덱스의 읽는 순서를 따른다. 정본: apps/docs/agent-read/에이전트-작업지침.md (§5 권한 규약 최우선).
  ```
- 공식 권장 패턴 그대로(`@AGENTS.md` 임포트). 심링크 대안은 배제(Windows 협업 대비).
- **[게이트]** 새 세션에서 자동 주입되는지 관측 → 기존 R5 종결.

### Phase 2 — 권한층 정렬 (G2 해소) 【필수 · ~5분】
- `.claude/settings.local.json` allow에서 **`Bash(git add:*)`·`Bash(git commit:*)`·`Bash(git pull:*)` 제거** → 프롬프트 복원.
- 프로젝트 공유 **`.claude/settings.json` 신설**(커밋 대상):
  ```json
  {
    "permissions": {
      "ask": ["Bash(git commit:*)", "Bash(git push:*)"]
    }
  }
  ```
  - deny가 아닌 **ask**: 지시받은 커밋은 한 번의 승인으로 가능, 무단 커밋만 차단(D3).
- (선택) PreToolUse 훅으로 push 차단 — v1에선 보류. ask로 충분한지 운용 후 판단.
- ⚠️ settings.local.json은 개인 파일(공유 안 됨) — 팀 강제는 settings.json이 담당.
- **[게이트]** 에이전트 세션에서 `git commit` 시도 시 프롬프트 뜨는지 확인.

### Phase 3 — 지침 ↔ 네이티브 기능 정렬 (G4 부분 해소) 【필수 · ~3분】
`agent-read/에이전트-작업지침.md` 3곳 수정:
1. §2 S1에 1줄: *"하네스가 플랜 모드를 지원하면 S1 게이트는 플랜 모드로 수행한다(계획 승인 전 편집 금지 — 게이트의 물리적 강제)."*
2. §11-2 독립 검토에 1줄: *"하네스에 리뷰 스킬(예: code-review 계열)이 있으면 독립 리뷰어 패스로 활용한다."*
3. §2 S4 절대경로(`/Users/soma/...`) → *"본 저장소 체크아웃에서 직접(워크트리 아님)"* 으로 상대화(§6 자기 원칙 정합).
- **[게이트]** 수정 diff 확인.

### Phase 4 — 경로 스코프 규칙 승격 (G3 완화) 【선택·후속 · ~15분】
- `.claude/rules/` 신설, §7 중 영역 한정 규칙만 복제(정본은 §7 유지, D1):
  - `bench-guard.md` (`paths: apps/api/src/modules/bench/**`) — tools/* 무인증·컨트롤러 가드 금지.
  - `web-navigation.md` (`paths: apps/web/**`) — 상태 기반 네비·로그인 2개·kind 구분.
- 효과: 해당 파일 작업 시에만 자동 로딩 — 지침을 안 읽은 세션에도 안전망.
- **[게이트]** 규칙 파일 내용 확인(정본과 불일치 없게 — L6 정합).

### Phase 5 — S0~S6 절차의 스킬화 (G4 완전 해소) 【선택·후속·갈림길 · ~30분+】
- 트레이드오프라 **사용자 결정 사안**:
  - **A) 스킬화**: `.claude/skills/s-flow/` 등으로 절차를 호출형으로 — 호출 시 지침 강제 로딩, 온디맨드. ↔ 단점: Claude Code 종속, aiqops와 이중 관리.
  - **B) 현행 유지**: 문서 단일 정본. Phase 1로 읽힘이 보장되면 실익 차이 축소.
- 본 기획서 권고: **B(보류)** — Phase 1~3 운용 후 재평가.

### (별도 저장소) aiqops 반영
- aiqops도 같은 구조 = 같은 G1 결함. 동일한 Phase 1(CLAUDE.md → `@AGENTS.md`)을 적용해야 함. **cherry 밖 작업이므로 별도 지시 시 수행.**
