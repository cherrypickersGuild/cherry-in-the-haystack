## 0. ⚠️ 왜 새 기획인가 — 방향이 바뀌었다

`../learning/1-work-guidelines.md`의 계획은 **화면(JSON) → 갭 리포트 → DB 역주입** 이었다. 실제로는 다음이 먼저 끝났다:

```
[원래 계획]  화면을 JSON 으로 작성 → 갭 도출 → DB 에 역주입 → API 전환
[실제 진행]  GraphDB 보완 → Postgres 이관(305개) → API → 화면이 DB 에서 자동 생성
```

**이관이 먼저 끝나면서 JSON 단계가 통째로 생략됐다.** 지금 12개 페이지는 사람이 쓴 것이 아니라 **온톨로지 설명으로 자동 생성**되고 있다.

### 그래서 "갭"의 뜻이 달라졌다

| | 이전(`../learning/ontology-gap/`) | **본 기획** |
|---|---|---|
| 묻는 것 | 온톨로지에 **개념·관계가 없나** (구조) | 페이지에 **내용이 비었나** (콘텐츠) |
| 예 | `Reranking` 노드 없음 | `Finetuning` 페이지에 Cherries 0건 |
| 상태 | **해소됨** — 이관으로 구조는 채워짐 | **지금부터** |

두 문서는 대체 관계가 아니라 **다른 층**이다. 구조 갭은 끝났고, 이제 콘텐츠 갭이다.

## 2. ⚠️ 이미 넣은 RAG 내용의 검증 수준 (정직하게)

RAG는 유일한 발행본이지만 **검증되지 않았다.**

| 항목 | 실제 |
|---|---|
| Overview 3문단 | 책 발췌를 읽고 **작성**. 문장별 근거 대조 **안 함** |
| Cherries 7개 | 원문 **앞부분(400~700자)만 보고** 요약. 전문 대조 **안 함** |
| MECE 여부 | 의도만 했고 **검증 안 함** |
| 연결한 문단 | 그 인사이트에 **최적인지 비교 안 함** |
| 외부 링크 | 실제 접속 **확인 안 함** |

→ **그럴듯하지만 "문헌이 실제로 말하는 것"이라고 보증할 수 없다.** 그것이 이 제품의 핵심 가치이므로(PRD §1 Cherries), 보증 가능한 상태로 만드는 것이 본 기획의 목적이다.

## 3. 목표

**① RAG 를 "보증 가능한" 수준으로 만든다** — 모든 주장에 근거가 있고, 링크가 실제로 열리고, MECE 가 검증된 상태.
**② 그 과정에서 품질 기준·절차를 문서로 남긴다** — 다른 사람이 같은 품질로 반복할 수 있게(검수자 인계 대비).
**③ 나머지 11개 토픽에 적용한다.**
**④ 293개는 등급을 나눠 처리한다** — 전수 수작업은 불가능.

## 5. 범위 · 등급

전수 수작업은 불가능하므로 등급을 나눈다.

| 등급 | 대상 | 채우는 수준 | 방법 |
|---|---|---|---|
| **A** | Learning 12개 토픽 | 4섹션 전부 · Q1~Q6 통과 | 사람 검수 |
| **B** | 자주 참조되는 개념(피참조 많음·하위 많음) | Cherries 자동 후보 + 사람 선별 | 반자동 |
| **C** | 나머지 | 온톨로지 설명만 (현 상태 유지) | 자동 |

- B 등급 자동화의 토대가 **이미 준비돼 있다**: `handbook.paragraph_embedding` 표 존재(0행) + `vector` 확장 설치됨. 문단 3,054개를 임베딩하면 체리 후보를 자동 추출할 수 있다.
- ⚠️ **자동 후보를 그대로 쓰지 않는다.** 반드시 사람이 고르고 다듬는다(Q1~Q2 때문).

## 6. 제약

- 🔴 공유 프로덕션 DB — 쓰기는 사전 승인(작업지침 §5·§7).
- **지어내기 금지** — 근거를 못 찾으면 비운다. 채우기 위해 만들어내지 않는다.
- 콘텐츠 언어는 영문(제품 UI 기준). 단 **온톨로지 설명의 한글은 그대로 노출**한다(사용자 결정).
- 검수는 다른 담당자에게 넘긴다(G4) → **절차와 기준이 문서로 있어야 한다.**
