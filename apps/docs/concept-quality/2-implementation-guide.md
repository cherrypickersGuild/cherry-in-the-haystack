## 1. RAG 검수 절차 (여기서 기준을 만든다)

### 1-1. 원문 전문 대조 (Q2)
체리 7건 각각을 **문단 전체**와 대조한다. 지금은 앞부분만 보고 요약했다.
- 대조 대상: `handbook.paragraph_chunk.body_text` 전문 (`chunkId` 로 조회)
- 판정: ⓐ원문에 있는 내용인가 ⓑ뜻이 바뀌지 않았나 ⓒ원문에 없는 말을 덧붙이지 않았나
- 결과를 **대조표**로 남긴다 — 이게 Q2 의 증빙.

### 1-2. 최적 문단 검증
"이 인사이트에 이 문단이 최선인가". 같은 주제를 더 잘 설명한 문단이 3,054개 중에 있을 수 있다.
- 후보 3개를 뽑아 비교 → 바꾸거나 유지 이유를 남긴다.

### 1-3. MECE 검증 (Q4)
체리가 덮는 **축**을 명시하고 표로 만든다.
```
현재 7축: 설계(라우팅) · 청킹 · 검색(하이브리드) · 리랭킹 · 최신기법 · 대안선택 · 미래
빠진 축 후보: 평가 · 비용/지연 · 실패모드
```
- 중복 축이 있으면 하나로 합치고, 빠진 축은 채우거나 "이번 범위 아님"을 명시.

### 1-4. Overview 근거 매핑 (Q1)
Overview 의 **문장 하나하나**가 어느 체리·원문에 근거하는지 매핑표를 만든다.
- 근거 없는 문장 → 삭제하거나 근거를 찾아 붙인다.
- ⚠️ 근거만 남기면 문단이 짧아질 수 있다. 그래도 **채우려고 지어내지 않는다.**

### 1-5. 표기 일관성 (Q5)
출처 표기(`책 / 챕터 › 섹션`), 용어 대소문자, 인용 형식.

## 2. 링크 설계 (Q3) — 지금 3/4 가 열리지 않는다

References 에 두 종류가 섞여 있다.

| 종류 | 현황 | 처리 |
|---|---|---|
| 외부 자료 | URL 있음. **접속 확인 안 함** | 자동 검사(HTTP) 후 죽었으면 교체·제거 |
| **소장 도서** | URL 없음 · **가리킬 화면 자체가 없음** | 아래 결정 필요 |

### 소장 도서 목적지 — 선택지

| | 방식 | 장 | 단 |
|---|---|---|---|
| **(가)** | 도서/챕터 페이지 신설 — 그 챕터가 어떤 개념에 기여했는지 + 문단 목록 | 자산이 쌓임 · 사이트 내 체류 | 작업량 큼 |
| **(나)** ⭐ | **원문 문단 모달** — 인용한 그 문단을 그대로 보여줌 | `chunkId` 가 이미 있어 **데이터 준비 완료** · 근거 확인이 제품 가치와 직결 | 책 전체 탐색은 안 됨 |
| (다) | 외부 구매 링크 | 제일 쉬움 | 근거 확인 불가 |

**권고 (나)** → 나중에 (가)로 확장.

### 링크 검사 자동화
- 외부 URL: 상태 코드 확인 → 죽은 링크 목록 산출
- 소장 도서: `chunkId` 또는 `book/chapter` 가 실제 DB 에 있는지 확인
- **죽은 링크 0 이 아니면 발행 불가**(체크리스트 게이트)

## 4-A. 기여자 기록 (2026-08-19 추가)

Overview 는 인용이 아니라 **우리가 쓰는 글**이다(PRD §1 — Cherries 만 *"what the literature actually says"* 로 규정). 따라서 Overview 에 필요한 것은 출처가 아니라 **저자 기록**이다.

- **연결 표 신설**: `content.concept_page_contributor` (`page_id` · `contributor_id` · `role` · `contributed_at`)
  SQL: `docs/architecture/concept-page-contributor-2026-08-19.sql` (롤백본 동봉)
- **역할 4종** — 원본 화면(`concept-reader-page.tsx`)의 3종 + Overview 작성용 `Author`.
  `CHECK` 제약으로 **다른 값은 DB 가 거부**한다.
  | 값 | 무엇을 한 사람 |
  |---|---|
  | `Author` | Overview 작성 |
  | `Evidence sourcing` | Cherries 수집 |
  | `Lead reviewer` | 전체 검수 |
  | `Concept mapping` | 개념 관계 (보통 자동) |
- **API**: `ConceptService.findContributors` 가 이 표를 조인해 **해당 개념의 기여자만** 반환(역할 순 정렬, `github_username` 우선). 없으면 빈 배열.
- **화면**: 오른쪽 `Knowledge Team` 카드. 비면 점선 자리표시자 + "No reviewer recorded yet."

⚠️ 리서처가 이름을 채워 보내면, 개발자가 **`handbook.knowledge_verification_contributor` 에 사람을 먼저 등록**한 뒤 연결 표에 넣는다.
