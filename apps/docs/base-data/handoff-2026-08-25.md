## 3. 작업 상세

### 3-1. 온톨로지 이관 (GraphDB → Postgres)

**왜 했나.** GraphDB는 원저자 로컬에만 있었고 호스팅된 적이 없다. 프로덕션이 못 쓰는 자산이었다. 그래서 **화면·API가 Postgres만 보면 되도록** 옮겼다.

**어떻게 했나.** 5단계, 각 단계가 파일로 남아 재현·감사 가능하다.

```
llm_ontology_v2-2026-08-19.ttl        (원본 TTL · python_services/packages/idea_to_graph_ontology/data/)
  → export-graphdb.cjs   →  ontology-snapshot.json   (apps/docs/ontology-migration/)
  → precheck.cjs         (dry-run 점검)
  → import-postgres.cjs --confirm     🔴 쓰기 · 단일 트랜잭션 · 재실행 안전
  → verify.cjs           (라운드트립 대조)
```

**검증 결과**: 건수 일치 · 이름/설명 불일치 0 · 관계 방향 불일치 0 · 순환 0 · 기존 데이터 무변경(chunk 3,054 / key_idea 3,067).

**⚠️ 함정 2개**
- TTL 내보낼 때 **`infer=false` 필수.** 안 하면 RDFS 추론으로 생긴 가짜 상위관계가 섞인다(실제로 한 번 섞여서 재추출했다).
- 개념 설명 5개가 `VARCHAR(1000)` 을 넘어 **트랜잭션이 통째로 롤백**됐다(DB 변경 0). 컬럼을 TEXT로 넓혀 해결. **대량 적재 전 `precheck.cjs` 를 먼저 돌린다.**

**전환 여지**: 관계 소스는 `ConceptRelationProvider` 인터페이스 뒤에 있다. GraphDB로 되돌리려면 `providers/graphdb-relation.provider.ts` 를 추가하고 `concept.module.ts` 한 곳만 고치면 된다. ⚠️ 단, **`CONCEPT_RELATION_SOURCE` env를 읽는 코드는 아직 없다**(문서·주석에만 존재).

`frontend-status-2026-08-25.md` 참조. **다음 에이전트가 반드시 지켜야 할 3가지:**

### 3-5. 읽기 전용 DB 계정 (2026-08-25)

외부 리서처가 매번 우리에게 추출을 요청하지 않도록 계정을 만들었다.

```sql
CREATE ROLE researcher_ro LOGIN PASSWORD '<사용자 지정>';
GRANT pg_read_all_data TO researcher_ro;
```

- **검증 통과**: 12개 스키마 108개 테이블 읽기 가능 · 쓰기 가능 테이블 **0개** · CREATE 가능 스키마 **0개** · 슈퍼유저/RLS우회 전부 false.
- 접속 host/port/db 는 `apps/api/.env` 의 `LOCAL_DB_*` 와 동일. ⚠️ **계정명은 `researcher_ro.<project-ref>`** (Supabase 풀러 형식).
- **비밀번호는 사용자만 안다.** 저장소·문서 어디에도 없다.
- ⚠️ `pg_read_all_data` 라서 **회원 정보 스키마도 읽힌다.** 범위를 좁히려면 이 권한을 회수하고 `GRANT USAGE/SELECT ON SCHEMA handbook, content` 로 바꾼다. **현재 전체 읽기는 사용자 판단이다 — 임의로 좁히지 말 것.**

## 7. 🔴 함정 · 주의

### 7-A. 🔴 `RAG.json` 을 커밋하면 안 된다

```

```

**소장 도서 본문 241문단이 그대로 들어 있다.** 파일로만 전달하고 Git에는 올리지 않는다.

⚠️ **현재 `deploy` 에서는 이 경로가 `.gitignore` 에 없다.** (제외 규칙은 `researcher-evidence-handoff` 브랜치에만 있다.) `git add -A` 하면 **그대로 커밋된다.** 조치 필요:
```
apps/docs/concept-quality/researcher-package/evidence-candidates/
```
를 `.gitignore` 에 추가하거나, 파일을 저장소 밖으로 옮긴다.

### 7-B. 과거에 실제로 낸 실수 (반복 금지)

| 실수 | 원인 | 방지 |
|---|---|---|
| 존재하지 않는 IRI `llm:VectorDatabaseX` 를 GraphDB에 넣음 | 원본을 안 보고 이름을 **추측**함 | 식별자는 **반드시 원본에서 확인**하고 쓴다 |
| 추론 트리플이 섞인 TTL 사용 | `infer` 옵션 미확인 | 내보낼 때 `infer=false` |
| 존재하지 않는 컬럼을 참조하는 서비스 코드 작성 | 스키마 미확인 | 쿼리 쓰기 전 `information_schema` 로 컬럼 확인 |
| 검색어 버그로 매칭 수가 크게 틀림 | 이름만 매칭 / 부분문자열 과다매칭 | 전체 구문 + 약어 단어경계 + 하위 개념명 + **별칭** |
| 문서가 코드보다 낡음(`toFill`·`hints` 등 사라진 필드를 계속 안내) | 인용부호 형태만 grep | **백틱 식별자 전부 추출**해 실재 여부 대조 |
| 이미 정해진 결정을 다시 제안(GraphDB 띄우기) | 검토 렌즈를 결정 이력과 대조 없이 적용 | 지적 전에 **이미 결정된 사안인지** 확인 |
| 제품 사양을 구현 편의로 축소(하위 개념을 모달로) | 사양보다 구현 난이도를 우선 | 사양대로 만든다. 못 하면 **사양 변경을 요청**한다 |

### 7-C. 데이터·용어

- `content.concept_page` 에는 `revoked_at` **컬럼이 없다**(다른 handbook 테이블엔 있다). 거를 때 `is_published` 를 쓴다.
- `lib/api.ts` 의 `fetchLearningConcept` 를 `fetchConcept` 로 되돌리지 말 것 — **KaaS용 동명 함수가 이미 있다.**
- `handbook.concept_alias` 의 컬럼명은 `alias_text` 다(`alias` 아님).
- 관계 ENUM 이름은 `handbook.concept_relation_enum` 이다(`..._type_enum` 아님).
