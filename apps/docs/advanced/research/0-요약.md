> **목적**: PRD가 정한 Learning > Advanced 6개 토픽을, 온톨로지에 개념을 새로 만들지 말지 판단할 수 있을 만큼 조사한다.

> 조사일: **2026-08-25** · 관련: `../../base-data/handoff-2026-08-25.md` §5-C · `../../concept-quality/` · `../../ontology-migration/`

## 0. 왜 조사했나

Advanced 6개 메뉴가 가리키는 온톨로지 개념이 **이름과 안 맞는다.** 6개 중 이름이 그대로 있는 건 1개뿐이다.

이렇게 된 이유는 단순하다. **PRD의 Advanced 토픽 이름과 온톨로지 개념 이름이 서로 따로 만들어졌고**, 화면을 붙일 때 가장 비슷해 보이는 개념에 연결했기 때문이다. 근거 문서가 있어서가 아니라 판단으로 붙인 것이다.

이제 지식팀이 없으므로 **온톨로지를 우리가 직접 고칠 수 있다.** 그래서 "무엇을 어떻게 고칠지"를 정하기 위한 조사다.

>                     손수 고른 검색어   실제 도구 기준(기획 적용 후)
> Advanced Prompting        126               83   (그중 45건이 "Reflexion" — 제외 시 38)

```

**305개 개념 중 2~3개 추가, 310건 관계 중 5건 안팎을 손대는 규모다.**

## 2. 조사에서 나온 공통 발견

### ① 검색어가 온톨로지 이름이면 재료를 못 찾는다

책이 쓰는 말과 온톨로지 이름이 다르다. 이게 "재료 0건"의 진짜 원인이었다.

```
온톨로지 이름                     책의 표현             후보 문단
MultiAgentSystem            →   multiagent            0건 → 71건
ParameterEfficientFinetuning →  LoRA · QLoRA · PEFT   0건 → 26건
HybridRetrieval             →   hybrid search         0건 →  6건
```
(실측값. 각 항목 문서 §7 참조)

**개념을 새로 만들기 전에, 검색어에 별칭·실제 표현을 넣는 것만으로 상당 부분이 해결된다.**

### ② 재료가 진짜 부족한 항목 — 🔴 **Custom Embeddings 는 사실상 0**

```
Custom Embeddings   도구 기준 1건 · 주제 적합 10건 안팎
                    contrastive 0건 · domain-specific+embedding 0건 · hard negative 1건
Multi-hop RAG       58건. 다만 직격 용어(multi-hop/multihop)는 5건뿐
```

**Multi-hop RAG 는 인접 재료(GraphRAG·query expansion)로 메울 여지가 있으나, Custom Embeddings 는 그것도 없다.**
→ **외부 자료(D6) 없이는 Custom Embeddings 페이지를 만들 수 없다.**

> 💡 `handbook.book.source_type` 에 `WEB_URL` 이 이미 있고 `source_url` 칼럼도 있다. **스키마 변경 없이** arXiv 논문을 넣을 수 있다.

### ③ 온톨로지에 이미 개념이 많다 — 신설보다 연결이 급하다

```
Advanced Prompting 관련   19개
Multi-hop RAG 관련        21개
PEFT/LoRA 관련            17개
Multi-agent 관련          25개
Custom Embeddings 관련    11개
Adversarial Eval 관련     23개
```

떠 있는 개념들(`QueryExpansion` · `Coordinator` · `PromptInjection` · `Guardrails` 등)을 **제자리에 이어주는 것만으로 페이지가 상당히 채워진다.**

### ④ Basics ↔ Advanced 경계는 대체로 깨끗하다

| Basics | Advanced | 경계 |
|---|---|---|
| Prompt Engineering | Advanced Prompting | 잘 쓰는 법 ↔ 추론 과정 설계 |
| RAG | Multi-hop RAG | 한 번 검색 ↔ 검색 결과가 다음 검색이 됨 |
| Fine-tuning | PEFT / LoRA | 무엇이고 언제 하나 ↔ 전체를 안 건드리고 하는 법 |
| Agents | Multi-agent | 하나가 어떻게 생겼나 ↔ 여럿을 어떻게 엮나 |
| Embeddings | Custom Embeddings | 무엇이고 왜 쓰나 ↔ 내 도메인에 맞게 다시 학습 |
| Evaluation | Adversarial Evaluation | 정상 입력에서 잘하나 ↔ 적대적 입력에서 안 무너지나 |

**여섯 쌍 모두 한 문장으로 갈린다.** 개념 신설의 근거가 된다.

### ⑤ 체리로 쓸 만한 "반전"이 각 주제마다 있다

| 주제 | 반전 |
|---|---|
| Advanced Prompting | 유명한 Self-Consistency가 실측에서는 Few-Shot CoT보다 못했다 |
| Multi-hop RAG | 핵심 난제는 "어떻게 찾나"가 아니라 **"언제 멈추나"** 다 |
| PEFT / LoRA | 65B 모델을 GPU 한 장(48GB)에서 파인튜닝한다 |
| Multi-agent | 프로덕션은 대부분 **순차 파이프라인 + 감독 한둘**이다. 자율 스웜은 드물다 |
| Custom Embeddings | 가장 유사한 문단의 **약 70%가 사실 정답**이라, 그대로 오답으로 쓰면 잘못 가르친다 |
| Adversarial Eval | 로버스트니스는 **모델 크기와 무관**하다. 적응형 공격자는 사실상 100% 뚫는다 |

## 4. 새 개념을 만들기로 할 경우 지켜야 할 것

1. **형제와 겹치지 않게** — 예: `MultiHopRAG` vs `GraphRAG` 경계를 문장으로 정의한다.
2. **순환이 생기지 않게** — 현재 순환 0건. 스크립트로 검증한다.
3. **출처를 구분** — `handbook.concept_relation.origin` 이 지금 전부 `graphdb-import` 다. 우리가 넣는 건 다른 값(예: `cherry-authored`)으로 넣어 **나중에도 구분**되게 한다.
4. **이름 규칙을 따를 것** — CamelCase · 영어 · 약어는 대문자 유지(`RAG` · `LoRA` · `PEFT`).
5. **설명 언어** — 기존 305개 중 275개가 한글이다. **기존 한글은 그대로 두기로 결정됨**(2026-08-25). 새로 만드는 것의 언어는 미결.
6. **TTL 역출력** — 지금은 `TTL → DB` 방향 스크립트만 있다. `DB → TTL` 내보내기 스크립트가 필요하다.

## 7. 조사 방법 (재현용)

- **외부**: 웹 검색 + 논문 원문 열람. 항목별로 서베이 논문을 우선 찾고, 거기서 분류 체계와 대표 기법 이름을 추출했다.
- **온톨로지 현황**: 라이브 Postgres 조회. `handbook.concept` · `handbook.concept_relation` 을 개념명 정규식으로 훑어 관련 개념을 뽑았다.
- **책 재료**: `handbook.paragraph_chunk.body_text` 를 단어경계 정규식(`\m...\M`)으로 검색해 건수를 셌다. 부분문자열 매칭은 과다 매칭을 일으켜 쓰지 않았다.
- 스크립트는 세션 스크래치패드에 있고 저장소에 커밋하지 않았다. 재현이 필요하면 `../../base-data/handoff-2026-08-25.md` 의 방식대로 다시 만들면 된다.
