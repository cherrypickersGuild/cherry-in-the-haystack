Embeddings & Vector Databases

Updated Aug 19, 2026· 5 cherries from 3 books· Draft — pending review· 7 min read
01 — Overview

An embedding maps a high-dimensional input — a word, a sentence, a document, an image, a user's interaction history — into a compact dense vector in a continuous space. Neural encoders (Transformers, CNNs, GNNs) or shallow models (Word2Vec, GloVe) are trained so that items with related meaning land close together, which turns "is this similar?" into arithmetic on vectors.

Why it matters: nearly every retrieval system in this handbook rests on this one trick. RAG retrieves by embedding similarity. Agent memory is stored and recalled as embeddings. If the embedding is wrong for your domain, every layer built on top of it inherits that error — and no amount of prompt engineering downstream will recover it.

The shape of the work: choose an embedding model, decide what unit of text becomes one vector, store the vectors somewhere that can search them quickly, and know where similarity stops being a good proxy for relevance.

🍒 Building Applications with AI Agents — Michael Albada

Ch.6 Knowledge and Memory › Implementing Semantic Memory with Vector Stores

Embeddings are vector representations that capture meaning from usage in large corpora, not from a dictionary. Word2Vec, GloVe and BERT place semantically similar words near each other in a high-dimensional space; LLMs have since improved these models further.

🍒 Building Applications with AI Agents — Michael Albada

Ch.6 Knowledge and Memory › Implementing Semantic Memory with Vector Stores

Vector stores — FAISS (Facebook AI Similarity Search), Annoy (Approximate Nearest Neighbors Oh Yeah) and others — exist because searching high-dimensional vectors is its own problem. They are built for fast approximate similarity search, which is what makes semantic memory retrievable at all.

🍒 LLM Engineers Handbook

Ch.4 RAG Feature Pipeline › Post-retrieval

Embedding similarity has a ceiling. A cross-encoder reranker scores the query against each retrieved chunk directly and finds relationships a similarity search cannot. But it is too expensive to run over the whole corpus — which is exactly why embeddings do the first pass and reranking does the second.

🍒 AI Engineering — Chip Huyen

Ch.6 RAG and Agents › Retrieval Optimization

Choosing a vector database is partly choosing an embedding strategy: which embedding models and vector search algorithms it supports, how long indexing takes, what bulk add/delete throughput it offers, and whether pricing is per vector or per query.

🍒 LLM Engineers Handbook

Ch.4 RAG Feature Pipeline › OVM

Working with embeddings deserves the same discipline as working with a database. The book's OVM (Object–Vector Mapping) pattern mirrors ORM: domain objects carry their own vectors, so embedding and storage stop being ad-hoc glue scattered through the pipeline.
