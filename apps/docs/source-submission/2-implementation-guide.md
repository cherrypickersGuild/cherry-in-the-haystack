## 0. 이 문서가 답하는 것

**"무엇을, 어디에, 어떤 순서로 만드나."** 그것만 적는다.

무엇을 만드는지·왜 그렇게 정했는지는 **기획서**에 있고, 화면이 어떻게 생겼는지는 **목업**에 있다.
여기에 그걸 다시 옮겨 적지 않는다 — 베껴 두면 한쪽만 고쳐졌을 때 어느 쪽이 맞는지 알 수 없게 된다.

| 궁금한 것 | 볼 곳 |
|---|---|
| 화면이 어떻게 생겼나 | **목업 2장** |
| DB 칼럼 · 상태값 | 기획 §7 |
| API 경로 · 권한 | 기획 §9 |
| 업로드 관문 순서 | 기획 §6-A |
| 무엇을 안 만드나 | 기획 §12 |
| 왜 그렇게 정했나 | 기획 §11 (D1~D16) |

**초기 구현이다.** 기획에 없는 것을 친절히 더하지 않는다. 예외 처리를 늘리지 않는다.

> 목업 JS 의 상태 코드 `HOLD` 는 DB 의 `ON_HOLD` 다. **코드에는 `ON_HOLD` 를 쓴다.**

## 1. 순서와 멈춤 지점

```
1 저장  →  2 투고  →  3 내 화면  →  4 관리자 화면  →  5 분석  →  6 미리보기  →  7 판단
        ↑
    여기서 한 번 멈춘다 — DB 칸 추가는 사용자가 직접 한다
```

| 단계 | 끝나면 무엇이 보이나 |
|---|---|
| **1. 저장** | 서버가 뜨고, 폴더에 파일이 생긴다 |
| **2. 투고** | 올린 파일·링크가 DB 에 행으로 남는다 |
| **3. 내 화면** | 유저가 자기 투고 목록을 본다 |
| **4. 관리자 화면** | 관리자가 목록에서 골라 원문을 본다 |
| **5. 분석** | [분석하기] 를 누르면 태그가 `진행 중 → 완료` 로 바뀐다 |
| **6. 미리보기** | 어느 칼럼에 무엇이 들어갈지 보인다 |
| **7. 판단** | 승인·유보·반려가 되고, 되돌릴 수 있다 |

**4까지 끝나면 "올리고 본다" 가 완성된다.** 5가 막혀도(→ §5-0) 거기서 끊고 쓸 수 있다.
**판단(7)이 맨 뒤인 이유** — 승인이 분석을 전제로 하기 때문이다(D9).

## 2. 1단계 — 저장할 자리

### 2-1. 폴더

기획 §2 · §8 대로 `UPLOAD_DIR` 을 잡는다. 로컬은 `./.uploads`(이미 `.gitignore` 에 있다), 서버는 `/data/uploads` 를 컨테이너에 연결한다.

**서버 폴더를 만들고 연결하는 것은 사용자 몫이다.** 에이전트는 로컬까지만 한다.

### 2-2. 저장 창구 하나

`submission-storage.service.ts` — 파일을 다루는 코드는 **여기만** 파일 시스템을 안다.

```
SubmissionStorage   save · read · remove          ← 나중에 S3Storage 를 이 자리에 끼운다
LocalDiskStorage    지금 쓰는 구현
```

- 저장하면서 크기와 SHA-256 이 같이 난다. 파일을 두 번 읽지 않는다.
- 키는 기획 §2 의 모양(`2026/09/<uuid>.<ext>`). **유저가 준 파일 이름은 경로에 쓰지 않는다.**
- `s3.service.ts` 는 건드리지 않는다.

### 2-3. 기동 점검

`UPLOAD_DIR` 이 없거나 그 폴더에 못 쓰면 **서버를 띄우지 않는다**(기획 §2).
로컬도 똑같이 막는다 — 로컬만 봐주면 설정을 빠뜨린 채 배포된다.

### 2-4. 🛑 여기서 멈춘다 — DB 칸 추가

SQL 전문은 **기획 §7**. 순서만 지킨다.

```
① ALTER TYPE … ADD VALUE 'ON_HOLD'   ← 이것만 실행하고 커밋한다
② 칼럼 7개 + 제약 + 인덱스            ← 커밋된 다음에
```

한 트랜잭션에 묶으면 안 된다. **운영 DB 라 사용자가 직접 실행한다.** SQL 을 드리고 기다린다.

> **검수표 1**

## 3. 2단계 — 투고 받기

모듈 하나를 만든다. `apps/api/src/modules/source_submission/`

```
source-submission.module.ts
source-submission.controller.ts     유저용 4개 (기획 §9)
source-submission.service.ts
submission-storage.service.ts       2단계에서 만든 것
upload-gate.service.ts              관문 — 기획 §6-A 순서 그대로
input-dto/submit-url.dto.ts
```

세 가지만 지키면 된다.

| | |
|---|---|
| **관문 순서** | 기획 §6-A 그대로. ⑥⑦ 에서 걸리면 **저장한 파일을 지우고 DB 행은 만들지 않는다** |
| **중복 응답** | 남의 것과 겹치면 `{duplicate:true, mine:false}` 만. 이름·상태·투고자를 주지 않는다(기획 §6-E) |
| **내 것만** | `mine` 은 `submitted_by_user_id` 로 거른다. **API 가 아예 안 준다** — 화면에서 거르는 게 아니다 |

**중복 확인 분당 20회**(기획 §6-E)는 `apps/api/src/main.ts` 에 이미 있는 경로별 리미터를 그대로 따라 쓴다
(로그인·구매 경로가 같은 방식으로 걸려 있다).

`app.module.ts` 에 모듈을 등록한다.

> **검수표 2**

## 4. 3·4단계 — 화면

### 4-1. 어디에 붙이나 — 먼저 정하고 시작한다

개발자 앱(`/`)은 URL 라우트가 아니라 **상태 기반**이다. 새 화면은 라우트 추가가 아니다.

| 화면 | 붙이는 곳 |
|---|---|
| **유저 투고** | 메뉴에 `Submit Source` 를 새로 만든다(D17) — `lib/nd-taxonomy.ts` 에 항목 + `app/page.tsx` 의 `switch` 에 분기 + `components/cherry/source-submit-page.tsx` |
| **관리자 검토** | `components/cherry/kaas-dashboard-page.tsx` 의 탭에 한 칸 추가(`isAdmin` 안쪽) + `components/cherry/source-review-panel.tsx` |

관리자 탭은 **기존 대시보드 안**이다(D6). 탭 키 타입이 `app/page.tsx` 까지 이어져 있으므로 양쪽을 같이 고친다.

### 4-2. 만들 것

```
apps/web/lib/submission-api.ts                    호출 모음
apps/web/components/cherry/source-submit-page.tsx   유저   ← 목업 그대로
apps/web/components/cherry/source-review-panel.tsx  관리자 ← 목업 그대로
```

**목업이 정본이다. 목업에 없는 것은 만들지 않는다.** 색·간격은 `kaas-admin-page.tsx` 를 따른다.

### 4-3. 관리자 쪽에서 주의할 것 둘

| | |
|---|---|
| **목록·상세는 파일을 안 준다** | 파일 본문도, 파일 주소도 응답에 없다. `/download` 를 눌렀을 때만 받는다(기획 §4-A) |
| **내려줄 때 헤더** | 기획 §6-B 의 헤더 + `Content-Disposition: attachment`. **화면에 띄우는 기능은 없다**(D20) |

관리자 API 는 `admin-submission.controller.ts` 에 모으고 **전부** `@Roles(Role.ADMIN)` 을 건다.

**링크는 서버가 건드리지 않는다.** 미리보기·파비콘을 가져오지 않으므로 서버가 투고된 주소로 요청을 보낼 일이 없다(기획 §6-F).

> **검수표 3**

## 5. 5단계 — 분석

### 5-0. 🛑 시작 전에 하나 확인한다

**`unpdf` 가 `node:20-alpine` 에서 도는지** 먼저 본다. 안 되면 `pdf-parse` 로 바꾼다.
이걸 안 보고 시작하면 이 단계가 통째로 헛일이 된다(기획 §13 U1).

### 5-1. 만들 것

```
analysis/analysis.runner.ts     여섯 단계 · 동시 실행 플래그
analysis/analysis.prompt.ts     기획 §6-D 의 다섯 가지
analysis/pdf-extract.ts         unpdf 감싸기
```

### 5-2. 어떻게 도나

```
POST …/analyze     상태를 RUNNING 으로 바꾸고 곧바로 응답한다. 처리는 뒤에서 이어간다
GET  …/analysis    화면이 몇 초마다 물어본다 (D10)
```

`analysis` 칸에 담는 것은 **기획 §7**. 단계·상태는 **기획 §4-B**.

| 상황 | 이렇게 한다 |
|---|---|
| 이미 돌고 있다 | `이미 분석 중입니다` 로 돌려보낸다. 줄을 세우지 않는다 |
| `DONE` 인데 또 눌렀다 | 다시 돌린다. 결과를 새로 덮는다(D13) |
| LLM 이 실패했다 | **재시도하지 않고 `FAILED`**(D18). 사유를 남긴다 |
| 서버가 죽었다 | 기동할 때 정리한다. **30분 넘은 것만**(D19) — 로컬과 프로덕션이 같은 DB 라서 다 끄면 남의 분석이 꺼진다 |
| 도중에 반려·유보했다 | `cancelled` 를 세우고 단계 사이에서 멈춘다 |

### 5-3. LLM 은 두 군데서만 부른다

④ 개념 뽑기(문단 묶음마다 · 시간의 대부분) · ⑥ 요약 정리(1회). 나머지는 규칙과 `knex` 다.

**Workshop 과 키를 나눠 쓴다**(기획 §1).

```
모델은 코드에 고정한다                BENCH_LLM_PROVIDER 를 따라가지 않게
SUBMISSION_ANALYSIS_ENABLED=false 면 [분석하기] 가 잠긴다
안 되면 그 자리에서 멈춘다             재시도 없음 · FAILED · 사유 표시 (D18)
```

### 5-4. 프롬프트

기획 §6-D 의 다섯 가지를 그대로 구현한다 — 본문은 구분자 안의 **자료**이고, 출력은 **정해진 JSON 만** 받고,
**도구를 붙이지 않고**, 새 개념은 **후보로만** 두고, **사람이 눌러야** 돈다.

**화면에는 경고를 띄우지 않는다.** 방어는 프롬프트 쪽에서 끝낸다.

> **검수표 4**

## 6. 6단계 — 적재 미리보기

`load-preview.service.ts` 를 만든다. `GET …/load-preview` 는 분석이 `DONE` 일 때만 표를 준다. 아니면 목업의 안내 문구로 막는다. 링크 투고에는 이 탭이 없다.

**칼럼은 라이브 DB 에서 읽어 쓴다. 문서에서 베끼지 않는다**(기획 §4-E).

```
① public.*    5표 — 표 이름과 행 수만
② handbook.*  6표 — 첫 행의 칼럼 전부 + 값·기본·빈칸·생성
```

화면에 **"②는 자동으로 되지 않는다"** 와 **행 수는 추정치라는 것**을 적는다(기획 §1 · §4-E).

> **검수표 5**

## 7. 7단계 — 판단 · 내보내기

경로는 기획 §9, 규칙은 기획 §4-D.

| | |
|---|---|
| **승인** | 파일은 분석이 `DONE` 이나 `FAILED` 일 때만. `NONE`·`RUNNING` 이면 거절. 링크는 제한 없음 |
| **다시 분석** | `RUNNING` 만 거절한다. `DONE`·`FAILED` 는 다시 돌아간다(D13) |
| **유보 · 반려** | 조건 없음. **사유는 받지 않는다** |
| **되돌리기** | 네 상태 어디에서든 다른 상태로 간다(D14). `reviewed_by_user_id`·`reviewed_at` 을 덮는다 |
| **승인의 뜻** | 파일은 "적재하기로 했다", 링크는 "등록하기로 했다" — **표시일 뿐 아무 행도 안 생긴다** |
| **내보내기** | 체크한 링크를 기획 §5-B 모양의 JSON 으로 준다 |

**가져오기(등록)는 다음 범위다.** 그때 지킬 것은 기획 §5-C 의 ⚠️ 블록에 적혀 있다.

> **검수표 6**

## 8. 건드리는 기존 파일

새 파일 말고, **이미 있는 파일 중 손대는 곳**은 이게 전부다.

| 파일 | 무엇 |
|---|---|
| `apps/api/src/app.module.ts` | 모듈 등록 |
| `apps/api/src/main.ts` | 중복 확인 경로에 리미터 한 줄 |
| `apps/api/package.json` | `unpdf` 추가 (5단계에서) |
| `apps/api/.env` | 기획 §8 의 변수 (커밋 안 함) |
| `.gitignore` | 로컬 업로드 폴더 제외 |
| `apps/web/lib/nd-taxonomy.ts` | 유저 화면 메뉴 항목 |
| `apps/web/components/cherry/kaas-dashboard-page.tsx` | 관리자 탭 한 칸 |
| `apps/web/app/page.tsx` | 위 둘의 연결 — 유저 화면 분기 + 대시보드 탭 키 |

그 밖의 기존 파일은 건드리지 않는다.
